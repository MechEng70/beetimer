# End-to-end tests

Real app, real AlarmManager alarms, on an emulator (never a phone), driven by Maestro. Results:
[REPORT.md](REPORT.md). Bugs found and every flow or analyzer change: [FIXES.md](FIXES.md).

## Run

```
./gradlew assembleDebug && adb -s emulator-5554 install -r app/build/outputs/apk/debug/app-debug.apk
python3 scripts/e2e/gen_flows.py          # regenerate flows after changing the generator
scripts/e2e/run.sh s1 s2 s3 s4 s5 s6 s7 s8 s9 s10 s11 s1x10 s2x10
python3 scripts/e2e/analyze.py            # writes docs/e2e/REPORT.md
scripts/e2e/screens.sh                    # re-captures docs/screenshots/app-*.png
```

Needs: a booted emulator (`emulator-5554`, AVD `beetimer-api36`, Android 16), the debug APK installed, and
Maestro. `run.sh` refuses any serial that is not an emulator. Run one batch at a time: two `run.sh` at once
break the Maestro device server. A full run takes about 35 minutes; each scenario has a 25-minute timeout.

## Scenarios

| | What it checks |
|---|---|
| s1 | Pan wand, wand stays in, 3 hives (vaporizer held through Keep sealed) |
| s2 | Pan wand, wand comes out, 3 hives (sealed hold overlaps the next hive's heat) |
| s3 | Gun type, 3 hives (10x) |
| s4 | Queue: skip to back, remove, a fourth hive |
| s5 | Cancel the vaporizer holder mid-block |
| s6 | Alarms: +1 min, Snooze, two close together |
| s7 | Screen off through a timed step |
| s8 | Process death mid-run (Home, then `am kill`, then `kill -9`; never `am force-stop`, which cancels alarms) |
| s9 | Editing steps while runs are active |
| s10 | Hive management: cap of 5, drag order, New session |
| s11 | App open: alarm screen opens in the app, Home and lock while ringing, snackbar instead of a notification |
| s1x10, s2x10 | s1 and s2 at 10x, for planner predicted vs actual |

## How it works

- Each scenario clears app data (emulator only), grants notification and full-screen permissions, sets the
  debug time scale in Settings (60x; s3, s1x10 and s2x10 use 10x), and runs its flow.
- Flows are generated by `gen_flows.py`. Waits scale with the time scale. The "autopilot" helper keeps
  tapping Done on alarms and Start/Done on rows until every hive is done, for the overlapping scenarios.
- Scenarios 7, 8, 10 and 11 have a shell part (`flows/s7.sh` and so on) for screen off, process kill, the
  long-press drag, and Home/lock checks. Shared shell checks are in `lib.sh`.
- `run.sh` streams logcat live (the buffer rotates otherwise) and writes per scenario to `docs/e2e/<s>/`:
  `log.txt` (the app's `BeeTimerE2E` event log and any `BeeTimerInvariant` errors) and screenshots. Raw
  Maestro output is git-ignored.

`analyze.py` fails a scenario on any invariant error, a failed flow, a crash, the vaporizer moving between
hives without being freed, or a failed scenario check. It reports the planner's predicted vs actual times for
s1, s2, s1x10 and s2x10.

## Known limits

- Android won't fire an exact alarm less than about 5 s ahead, so at 60x the 2.5 s heat step rings at about
  5 s. That is why s3 runs at 10x.
- s2 at 60x fails one check (Hive 1's sealed hold overlapping Hive 2's heat): the hold lasts 10 s and the
  autopilot can't get Hive 2 heating in time. It passes at 10x (s2x10). The check was not loosened.
- If the Maestro device server dies at startup, rerun that scenario. If a run was interrupted, kill any
  leftover Maestro JVM before the next batch.
